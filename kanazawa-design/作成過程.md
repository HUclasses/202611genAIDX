## 0. きっかけ（人の問い）

「金沢市の DESIGN.md のようなものはないのだろうか？普通のデザインガイドでもいい」

→ 調べた結果、**Web 向けのデザインシステムは金沢市から公開されていない**。ただし、金沢らしさを**数値で決めた文書**はすでにあった。

| 見つかった文書 | 中身 |
|---|---|
| 金沢市景観計画「色彩基準等について」 | 推奨色「木色」の範囲と禁止色がマンセル値で書かれている |
| 金沢市屋外広告物ガイドライン | 「目立つより、地域に溶け込む」という考え方 |
| 「木の文化都市・金沢」ロゴ使用マニュアル | 色指定・最小サイズ・余白などの使い方の決まり |
| デジタル庁デザインシステム（DADS） | 行政 Web 向けのフォント・サイズ・部品の決まり（MIT ライセンス） |

**講演で言えること**：「ゼロから作る」のではなく、**組織にすでにある暗黙のルールを、AI が読める形に翻訳する**のが出発点になる。

## 1. 器を決める：DESIGN.md の書式を確認

- Google Labs が 2026年4月に公開した書式（Apache 2.0、まだ alpha）。
- 1つの Markdown ファイルに、**機械が読む数値（YAML）** と **人が読む意図（文章）** の二層で書く。
- 決まった章立て：Overview → Colors → Typography → Layout → Elevation → Shapes → Components → Do's and Don'ts。

## 2. 色を数値に翻訳する（ここが一番の山場）

景観計画の色はマンセル値（例：7.5YR 5/3）で書かれていて、画面の色（#90745E のような HEX）にはそのままならない。

- Python のライブラリ（colour-science）で変換するスクリプトを AI に書かせた（`munsell.py`）。
- 推奨範囲（5YR〜2.5Y × 明度4〜7 × 彩度2〜4）を一覧表にして、まず「金沢の木色とはこういう色の幅」と目で確かめた。
- 中心の **7.5YR 5/3 = #90745E** を代表色「木色」にした。
- 変換が正しいかの確認：灰色の N5 が #797979 になる（一般的な値とほぼ一致）。

## 3. 景観のルールを、画面のルールに読み替える

人が決めた方針（AI に任せず、こちらで判断したところ）：

1. **禁止色の彩度上限を、すべての色に自主的に適用する**
   （R・YR 系は彩度6まで、Y 系は4まで、その他は2まで）。
   → アクセントの紅殻（10R 3/6）も、金箔（2.5Y 7/4）も、ちょうど上限の色にした。
2. **景観計画には「文字」の色がない** → 推奨色と同じ色相のまま明度を下げ、墨色（7.5YR 2/1）を作った。
3. **景観計画は外壁のためのルールで、Web に守る義務はない** → 「金沢らしさの手がかりとして借りる」と DESIGN.md に明記した。

## 4. 読みやすさを数値で確かめる

- 文字と背景のコントラスト比を計算（WCAG：本文は 4.5 以上）。
- 結果：本文 11.82、主要ボタン 9.25、リンク 8.33 など、**景観ルールを守ったままでも基準を満たせた**。
- 一方で、代表色の木色そのもの（3.92）は文字には足りない → 「木色を本文の文字色にしない」を Don'ts に追加。
- **発見**：エラー色と紅殻が似てしまう（赤系は彩度6までなので）→ 「エラーには必ずアイコンと文言を添える」をルール化。
  **制約があると、色以外の手がかりを使う設計に自然と向かう**。

## 5. 書いて、機械にチェックさせる

- DESIGN.md を書き、Google 公式のチェックツールで検査：
  `npx @google/design.md lint DESIGN.md`
- 1回目：エラー0、警告16（定義したが使われていない色がある）。
  → 色の役割（primary など）を基本色への参照に直し、部品を追加して、**警告0**にした。
- 同じツールで `tokens.json`（デザイントークンの標準形式）と Tailwind 用の設定も書き出した。
- さらに独自の検査（`check_kinshi.py`）：全色を HEX からマンセル値に戻し、禁止色ルールに収まるかを自動判定。
  → 全色ルール内。比較として、Web でよく使う青（#0066CC）は彩度14.6、赤（#E60012）は18.3で、**どちらも金沢の景観では禁止色の範囲**。

## 6. 使ってみる

- DESIGN.md だけを守って、架空の「事業承継セミナー申込」画面を作った（`preview.html`）。
- 紅殻を使ったのは「主要ボタン」と「現在地の下線」の2か所だけ。目立たせたいところは余白と太字で出している。

## 講演で使えそうなポイント

- **「AI に何を任せ、何を自分で決めたか」が見える例**：変換や検査（計算）は AI、ルールの読み替え（判断）は人。
- **専門知識が効く**：マンセル値・景観行政・アクセシビリティを知っている人ほど、良い DESIGN.md が書ける。AI はその知識を形にする速さを上げる道具。
- **既存の資産を活かす**：新しいルールを作らなくても、組織の文書の中にもう材料がある。
- **ルールは機械で検査できる形にすると強い**：lint や自動判定で「守れているか」をいつでも確かめられる。

## ライブデモにする場合の案

同じ指示（「事業承継セミナーの申込画面を作って」）を、
(a) DESIGN.md なし、(b) DESIGN.md あり で AI に出させて並べる。
(a) はたいてい青系の汎用的な画面になり、(b) は木色の画面になる。

## 7. 改訂（v2「公式サイト調」・非公式版）：v1「木色」は淡すぎた → v2「公式サイト調」（2026-11-18）

**人の判断**：v1 でフライヤーを作ってみたら「淡すぎる」。原因は、参照した基準が**建物の外壁用**だったこと（街並みに溶け込むための基準を、目を引くべき印刷物に使った）。

**やったこと**

1. もっと用途に合う基準を探し直した → **金沢市カラーユニバーサルデザインガイドライン**（印刷物・サイン向け）が見つかった。ただし色の数値の指定はなく、「明暗差をつける」「色だけに頼らない」「黄色・水色を細い線に使わない」などのルール集だった。
2. 色そのものは、**金沢市公式ホームページを実際にブラウザで開いて計測**した（スタイルシートの使用回数と、画面上の面積）。
   - 深紅 #990000（最多）、生成り #F8F5EE、砂 #F1E9D5、本文 #333333、リンク #2D5F92、飾りの金 #E8BB5E、書体は游ゴシック、角丸は 2〜6px。
   - 見出しは中央そろえ＋金の市松の飾り＋英語の副題、タブは深紅の塗り、という部品の作りも観察で拾った。
3. 2つを重ねて DESIGN.md v2 を作成（lint エラー0・警告0）。

**発見（講演ネタ）**：色覚シミュレーションをかけると、公式サイトの深紅 #990000 は P型の見え方で本文の #333333 とほぼ同じ暗さになる（コントラスト比 1.04）。カラーユニバーサルデザインガイドラインが「濃い赤は黒と見分けにくい」と書いているとおり。→ 「深紅で強調するときは太字・下線も付ける」を v2 のルールにした。

**講演で言えること**

- 最初の出力を見て「何か違う」と感じ、**その理由（参照元の用途違い）を言葉にできたこと**が改善の起点。AI はそこまでは教えてくれない。
- 元にする資料を変えれば、同じ手順で別のデザインシステムができる。手順（調べる→数値にする→検査する→使ってみる→見直す）は再利用できる。
- フライヤーのキャンバスに v1 と v2 を並べてあるので、比較スライドにそのまま使える。
